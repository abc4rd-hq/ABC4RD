# ABC4RD Identity — Keycloak

Этот каталог разворачивает единый вход ABC4RD рядом с Open edX. Этап 4А
ограничен установкой и внутренней проверкой Keycloak: OIDC-интеграция с
Open edX и изменение конфигурации Tutor в него не входят.

## Состав

- Keycloak `26.7.0` в production-режиме;
- PostgreSQL `17.10` только во внутренней Docker-сети;
- готовность к будущему публичному адресу `https://id.abc4rd.org` через Caddy
  из Tutor;
- закрытые снаружи административные, master, health и metrics-маршруты;
- постоянный том базы и автоматический запуск после перезагрузки.

Секреты не хранятся в Git. На сервере они находятся в
`/opt/abc4rd/keycloak/.env` с правами `0600`, а мастер-копия хранится в
1Password vault `ABC4RD`.

## Этап 4А — установка и внутренняя проверка

1. Скопировать каталог в `/opt/abc4rd/keycloak`.
2. Создать серверный `.env` из 1Password и установить права `0600`.
3. Проверить Compose, собрать образ и выполнить первый запуск с одноразовым
   bootstrap-overlay:
   `docker compose -f docker-compose.yml -f docker-compose.bootstrap.yml up -d --wait`.
4. Создать постоянного администратора, удалить временного bootstrap-admin и
   пересоздать Keycloak базовой командой `docker compose up -d --wait`, чтобы
   bootstrap-секрет больше не находился в окружении контейнера.
5. Создать realm `abc4rd` с `enabled=true` и
   `registrationAllowed=false`.
6. Проверить версии, health обоих контейнеров, внутренний OIDC discovery,
   отсутствие пользователей, лимиты ресурсов, закрытые host-порты и
   политику автозапуска.

Подключение Tutor-плагина, `tutor config save`, пересоздание Caddy и OIDC
настройки Open edX на этапе 4А не выполняются.

## Будущий публичный этап

После публикации A-записи `id.abc4rd.org` на production IPv4 отдельно
применяется Caddy-фрагмент из Tutor-плагина. Только после получения
доверенного сертификата проверяется публичный discovery endpoint и внешняя
блокировка `/admin`, `/realms/master`, `/health` и `/metrics`.

## Критерий готовности

- оба контейнера имеют состояние `healthy`;
- внутренний discovery realm `abc4rd` отвечает HTTP `200`, realm включён,
  публичная регистрация выключена, пользователей нет;
- у контейнеров нет опубликованных host-портов, PostgreSQL остаётся только во
  внутренней Docker-сети;
- задана политика `restart: unless-stopped`, Docker включён в автозапуск.

Фактическое восстановление после перезагрузки подтверждается только отдельным
согласованным reboot-тестом; этап 4А не требует принудительной перезагрузки VPS.
